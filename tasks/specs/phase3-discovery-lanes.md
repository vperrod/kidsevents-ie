# Phase 3 spec — discovery lanes for all three catalogues, 32 counties

Plan §4.3, §11/§12 (the source lists). Builds on phase 1 (contract, `promote()`), phase 2 (`llm.complete`, `routing.jsonl`). Exclusions: no photo/media work (phase 4), no admin views (phase 5 renders what `factory_state.json` and the staged files expose), nothing on the mini PC except the crew's query list already shipped in 0b.

## Architecture
- `discovery/` package on the VM: `lanes/<name>.py`, each exposing `run(state) -> list[Candidate]` where `Candidate = {source_url, title?, text?, kind_hint?, found_via: "<lane>:<key>", county?, fetched_at}`; a shared `ledger.py` (`discovery/ledger.json`, url → first_seen/last_seen/status) so a URL is researched once and re-checked no sooner than `RECHECK_DAYS` (events 3, places 30, holidays 60); all writes via `write_json_atomic` under `output_lock`.
- One entry point `factory_worker.py run_discovery_cycle()` → `discovery.run_all(budget)` → new candidates appended to `staged/candidates.json` (the same ledger the social crew feeds; social items already have the same keys) → `promote()` per candidate through the phase 1 steps → on-air / needs-input / rejected. Per-cycle budget: `MAX_CANDIDATES_PER_CYCLE=60`, `CYCLE_WALL_SECS` from phase 2.
- Every lane records `{lane, key, found, new, errors, ms}` into `factory_state.json.lanes[]` for the Sources area.

## Lanes (all free; each has an `enabled` flag in `catalog/lanes.json`, plus keys)
1. `listings` — the deep listing URLs in `sources.json` (extend to every county: yourdaysout per-county slugs for all 32; discoverireland.ie/events; council/library event pages from plan §12.2 that returned 200) — crawl with the existing crawl4ai path, harvest JSON-LD `Event`, and for pages without JSON-LD pass the page text to `promote()` as a listing (the classify step decides kind; a listing page yields many events → split by the LLM into ≤10 candidates with their own detail URLs when present).
2. `feeds` — RSS/Atom/ICS URLs in `catalog/lanes.json` (start with the council calendar exports found in §12.2 for Cork County, South Dublin, Kildare, Monaghan; `icalendar`-free parsing with stdlib for VEVENT; `xml.etree` for RSS).
3. `sitemaps` — `sitemap.xml` of each curated domain, filtered to URLs matching `event|whats-on|things-to-do|family|kids`, new URLs only.
4. `search` — searchgw only (`_src_gateway`), templates from plan §12.2 × county × season (`catalog/search_templates.json`; season = current month → the seasonal subset: santa/christmas/panto Oct–Dec, halloween Sep–Oct, summer camps Mar–Jun, easter Feb–Mar, midterm Sep/Jan), max 40 queries per cycle rotating through counties so every county is queried at least weekly.
5. `opendata_places` (weekly) — Fáilte Ireland Open Data (needs the `data@smalldays.ie` registration → key in the sops store; until then the lane logs "no key" and skips), data.gov.ie tourism-activities-and-attractions CSV, data.gov.ie/Smart Dublin playground + park datasets, OSM Overpass for the island (`leisure=playground|water_park|nature_reserve`, `tourism=museum|attraction|zoo`, `amenity=library`, `natural=beach`; one bbox query per province, 10 s sleep between), Coillte recreation sites (page crawl), Blue Flag list (page crawl). Each row becomes a place candidate with `location` pre-filled (lat/lon/county from the data), `kind_hint=place`, `found_via="opendata:<dataset>"`; `promote()` still runs the write step so descriptions are grounded in the source page (official site if the dataset has it, else the dataset row itself as the fact).
6. `wikidata` (weekly) — SPARQL: Irish museums/attractions/zoos/parks with P856 (website), P2003 (Instagram), coordinates; merged into existing places by name-fold+geo, else new candidates.
7. `ticketmaster` — Discovery API (key from the vault item "developer-account.ticketmaster.com" → sops store `vm/kidsevents.env` as `TICKETMASTER_API_KEY`), `countryCode=IE`, `classificationName=Family`, daily, `size=100`, respecting the 5,000/day quota (log calls).
8. `holidays_seed` (weekly) — Wikivoyage + Wikidata tourist destinations (`wd:Q... touristType families` where present) + an LLM-generated seed list of 100 family destinations (one call, cached in `catalog/holiday_seeds.json`, each then researched: Wikivoyage page as source 1, official tourism site from Wikidata P856 as source 2), Open-Meteo climate normals for `best_months`, OpenFlights routes from DUB/ORK/SNN for `direct_flight` and `flight_time_from_dublin` (great-circle distance / 800 km/h). Social family-travel tags come through the mini PC crew's `holidays` query set (already routed via `found_via`).

## Verification (real, in the report)
- `pytest test_discovery.py` (ledger recheck logic, ICS/RSS parsing on fixtures, template expansion counts, Overpass response parsing on a fixture).
- One real cycle with lanes 1–4 enabled: `factory_state.json.lanes[]` numbers, candidates added, promote outcomes (on-air / needs-input / rejected counts with top reasons), wall time under `CYCLE_WALL_SECS`.
- One real run of lane 5 (OSM + data.gov.ie only, Fáilte skipped without key) for one province: rows fetched, places created, sample record.
- One real run of lane 8 for 5 destinations: the two sources per destination and the resulting holiday record or reason.
- Counts on air after: events per county (≥20 counties non-zero), places ≥300, holidays ≥5 (target ≥50 grows over the following weekly runs).
- Commit + push with the two trailers. Stop.
