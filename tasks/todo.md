Also: the extract step's location hint is now the candidate's `county`, not its `found_via` provenance tag (the phase 1b cleanup note)
- [x] Two bugs found by real execution, both fixed and verified live: (1) `_crawl_pages`' 220-line/4,000-character cap is the budget for a page that IS the item, and a listing page's links start far past it — a yourdaysout county page spends its first 4,000 characters on a cookie notice and reaches its first real link at character 27,836, so lane 1 was feeding `promote()` consent text and getting "not an event" every time. The cap is now a parameter, the lane crawls wide, and the page is reduced to its own link index in code before one model call picks the items. (2) three separate ways the pipeline would have stalled after its first pass: `sitemaps`/`opendata_places`/`wikidata` truncated to their per-source cap *before* the ledger filter, so they re-offered the same first N URLs for ever (`found=15, new=0`) and never reached item N+1; `feeds` stopped reading feeds once the cycle budget was met, so the feeds at the end of the list were only ever read on a quiet cycle; and the desk deduplicated by `source_url` against its whole history, which would have silently dropped every URL coming back for its 3/30/60-day recheck. All fixed — the first verified by running each lane twice against the ledger (zero overlap), the second by confirming all six feeds are read every cycle, the third by five new tests
