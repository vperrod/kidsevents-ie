- [x] Two bugs found by real execution, both fixed and verified live: (1) `_crawl_pages`' 220-line/4,000-character cap is the budget for a page that IS the item, and a listing page's links start far past it — a yourdaysout county page spends its first 4,000 characters on a cookie notice and reaches its first real link at character 27,836, so lane 1 was feeding `promote()` consent text and getting "not an event" every time. The cap is now a parameter, the lane crawls wide, and the page is reduced to its own link index in code before one model call picks the items. (2) three separate ways the pipeline would have stalled after its first pass: `sitemaps`/`opendata_places`/`wikidata` truncated to their per-source cap *before* the ledger filter, so they re-offered the same first N URLs for ever (`found=15, new=0`) and never reached item N+1; `feeds` stopped reading feeds once the cycle budget was met, so the feeds at the end of the list were only ever read on a quiet cycle; and the desk deduplicated by `source_url` against its whole history, which would have silently dropped every URL coming back for its 3/30/60-day recheck. All fixed — the first verified by running each lane twice against the ledger (zero overlap), the second by confirming all six feeds are read every cycle, the third by five new tests. (3) `promote()` only ever called a *classify* outage a lane outage; an extract or write step that no lane answered fell through as needs-input ("no title could be read from the source"), which the ledger then stamped — so a record nothing was wrong with would not be looked at again for 3–30 days because of one busy night. ## Post-launch: holidays catalogue was empty, places filter was huge (2026-09-14)
- [x] `834b532`: root cause of "no holidays" was not the seed list or the gate -- it was that `holidays_seed` (and `wikidata`/`ticketmaster`/`opendata_places`) had **never run once since launch**. `run_all()` gave each cycle's budget to `LANE_ORDER` first-come; `listings`/`feeds`/`sitemaps` alone reliably filled the whole 60-candidate budget every cycle, every hour, forever, so every lane after them logged "budget spent" and never even called `.run()`. Fixed: budget now splits evenly over however many lanes are runnable this cycle.
- [x] Once `holidays_seed` finally got a turn, two more bugs surfaced immediately (confirms the project's own lesson: nothing here is verified until it runs for real). `classify()` read a destination's own Wikivoyage article as `kind="place"`, and the on-island-of-Ireland gate then correctly rejected Benidorm for being in Spain -- correct for a real place, wrong for a holiday the model misread. Then, once that was fixed, `classify()`'s `family_relevant` came back `False` with reasoning "not Ireland" for the same destinations -- the classify prompt is written Ireland-first and the model conflated location with family-suitability. Both fixed the same way: `promote()` now trusts a candidate's own `kind_hint` (which `holidays_seed` already sets to `"holiday"` for every candidate it hands over, since the lane only ever seeds "destinations Irish families actually travel to with children") over classify()'s free-text guess for both kind and family-relevance.
- [x] Verified live, not just by test: reset `holidays_seed`'s cursor and cleared the wrongly-rejected ledger entries, re-ran three times as each bug surfaced, confirmed real destinations publish under the fixed code. 103 discovery tests + 17 gate tests still green.
